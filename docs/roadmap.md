# Project plan

GOAT AI's first goal is a **verified, headless GOAT duel that two random agents can finish**. Playing strength comes after rule correctness and information isolation. This plan uses evidence gates rather than calendar dates: a milestone is complete only when its exit criteria pass on a clean checkout.

## Current baseline

The repository has a Python environment contract, observation and action types, three baseline agents, and JSON trajectory serialization. Tests run locally; GitHub Actions is disabled for this project. The default engine raises `SimulatorUnavailable`. A restricted native adapter now completes normal-monster fixture duels; this is not a historical correctness claim. The selected engine is modern ocgcore with `DUEL_MODE_GOAT`, subject to ruling validation. See [native setup](native_setup.md).

## M0 — Prove the native engine path

**Status: complete for the first-decision prototype.** Reproduction and exact pins are in [native setup](native_setup.md). The implementation uses a direct `ctypes` binding; M1 must still decode responses and enforce player-visible observations.

**Work**

1. Pin exact ocgcore, card database, and script revisions with URLs, hashes, licenses, and reproducible setup instructions. Keep third-party artifacts out of Git.
2. Build and call the native core from a minimal Python harness. Use an explicit GOAT rules flag, 8000 LP, five opening cards, first-turn draw, and a fixed seed.
3. Inspect native decision messages, query APIs, and card/script loading. Record which message types and state queries are needed for full duels.
4. Decide between a direct C API binding and a patched ygoenv fork using a small measured prototype. The choice must preserve unrestricted legal option counts and player-scoped views.

**Exit:** A reproducible command starts a real GOAT-mode duel, reaches its first decision, and records the exact native versions and seed. A test checks the opening draw. Any unsupported message fails explicitly.

## M1 — Complete a duel safely

**Status: in progress.** A direct native binding completes restricted fixture duels with selected scripted cards. It handles optional chain choices, exposes structured public chain links, monster battle positions, and Battle/Damage Step timing from public core events, and redacts the ID of a set opponent monster targeted by Nobleman. Observations include a bounded history of public turn, phase, attack, Damage Step, and chain events, the player's sorted initial Main Deck and own Fusion Deck identities, narrow memory of opponent field cards publicly seen before turning facedown with their field slots, public Deck-top reveals, recipient-scoped card reveals, the active disabled-zone mask, and a public Scapegoat summon restriction. Unrevealed opponent identities remain hidden. `.ydk` parsing, pinned whitelist checks, deterministic deck shuffling, and a complete metadata/script-path inventory for the 1,685 allowed whitelist IDs are implemented. Deck validation admits more than 60 Main Deck cards and selects historical or community Side Deck sizing. A separate experimental adapter completes 50 seeded synthetic control-deck duels and 20 cross-deck duels against a Chaos-style probe, including effect yes/no prompts. It now decodes bounded multiple-zone selection, Attribute announcement, and number announcement prompts; native fixtures exercise Ground Collapse, Homunculus the Alchemic Being, and Wall of Revealing Light respectively. Question fixtures reach a 1,039-name Monster announcement, redact the activating player's Graveyard during the chain, and confirm both ordinary and GOAT-variant printed-name branches. The historical announcement catalog still needs independent validation. A Fruits of Kozaky's Studies fixture covers a three-card private Deck-top ordering prompt. An Exchange fixture verifies that privately revealed opponent hand cards become selectable only for the addressed player, without exposing native hand slots. A Nobleman Flip-monster fixture verifies that full Deck reveals are delivered only to their addressed recipients. A reproducible random-deck probe generated ten whitelist-legal 40-card decks and completed all ten seeded 3,000-decision-limit duels in 12,382 decisions on the pinned assets; the report hash reproduced. Differential tests cover hidden opening-hand, set-monster, set-Trap, targeted set-Trap, and opponent Extra Deck identities, but broader decisions and visibility remain unaudited. General effect and decision coverage, independently audited historical legality, and complete player-visible observations are still required. Face-up monster ATK, DEF, and counters are now included, but other dynamic public card state remains unaudited.

**Work**

1. Implement `.ydk` parsing and April 2005 deck/card-pool validation. Begin with two small legal fixture decks and expand coverage.
2. Convert each native decision request into a variable-length list of structured actions. Map selected actions to exact native responses, including multi-step targets, effect choices, chains, and phase changes.
3. Build observations solely from player-visible native queries and observed public events. Maintain known-card memory without reading hidden identities from internal state.
4. Connect the adapter to `GoatEnvironment`; run two `RandomAgent` instances through terminal states. Record decision trajectories and replay seeds.
5. Add an interactive CLI duel and a real benchmark command. Record crashes, unsupported requests, and infinite loops as failures.

**Exit:** A clean setup completes seeded random-agent duels with valid outcomes and no unhandled native messages in the fixture decks. Illegal actions are rejected. Repeated seeds reproduce action/observation/outcome traces. Changing a hidden opponent hand or deck order while holding the visible state fixed cannot change the observation supplied to the agent.

## M2 — Historical correctness gate

**Status: in progress.** The source-backed Cannon Soldier / Book of Moon fixture checks historical Ignition priority after a summon, the GOAT Nobleman fixtures check a representative banish ruling and Flip-monster Deck verification, two Field Spell fixtures check replacement and chained destruction, a Dekoichi fixture checks a basic Flip Effect draw and Book of Moon's Damage Step restriction, a Peten fixture compares missed timing after Cannon Soldier's cost with a successful battle trigger, a Sangan/Thestalos fixture checks mandatory trigger ordering and reverse chain resolution, and a Solemn Judgment fixture checks Normal Summon negation. Pre-errata Dark Magician of Chaos fixtures check Spell recovery after its two-Tribute Normal Summon and its face-up versus face-down leave-field destination when tributed by Cannon Soldier. A Goat Control fixture follows Scapegoat into Metamorphosis for Thousand-Eyes Restrict, equips an opposing monster, then uses Tsukuyomi to set Restrict and checks the hidden view. Scapegoat fixtures check four token placements, the four-vacant-zone requirement, same-turn Summon restrictions, a legal monster Set, token tribute for Cannon Soldier but not a Tribute Summon, and restoration of Summon permission after Solemn negates its activation. Common-staple fixtures check Graceful Charity's draw and discard choices, Delinquent Duo's random and chosen discards without exposing opponent hand cards, Snatch Steal's control and Standby Phase recovery followed by Heavy Storm returning the monster, and Book of Moon setting the stolen monster while control remains with the stealing player. A Mirror Force and Book of Moon attack-response fixture checks that the chained face-down attacker survives while another Attack Position monster is destroyed. A Torrential Tribute and Book of Moon summon-response fixture checks that the face-down monster is still destroyed with the other monster. Pre-errata Ring of Destruction fixtures check own-monster targeting and equal damage, plus Breaker removing its Spell Counter as a cost before Ring deals 1600 damage and the pending Breaker effect destroys a set card. Chaos Sorcerer fixtures check the LIGHT/DARK Graveyard summon cost, opponent-monster banish, and same-turn attack restriction, a negative field-only cost case, and Book of Moon making the target invalid while still spending Sorcerer's effect and attack opportunity. A GOAT Black Luster Soldier fixture checks its LIGHT/DARK Graveyard summon cost, optional second-attack trigger after battle destruction, direct second attack, two-attack limit, and alternative monster-banish effect with its same-turn attack restriction, plus loss of that effect after a declared attack. A pre-errata Sinister Serpent fixture checks optional Standby Phase return after a discard, including its public Graveyard and private hand boundaries. A Tribe-Infecting Virus fixture discards Serpent as an activation cost, limits Type announcements to face-up monsters, destroys the declared opponent Type, and returns Serpent on the next Standby Phase. A Book of Moon response branch verifies that Tribe does not destroy a monster turned face-down after its Type was declared, and checks the resulting hidden field view. Paired Premature Burial fixtures verify its 800 LP revival cost and the different outcomes when Book of Moon breaks the Equip link by turning the monster face-down versus Mystical Space Typhoon destroying the Equip Spell, and a chained Typhoon preventing the initial revival after the 800 LP cost is paid. Call of the Haunted fixtures check that Book of Moon severs the revived monster while Call stays face-up and the face-down monster remains, and that the two Call/Mystical Space Typhoon chain orders differ in whether a Summon is attempted before both cards and the monster end in the Graveyard. Airknight Parshath fixtures check piercing damage and its mandatory draw against a set monster, Waboku preventing both damage and the draw, and Airknight drawing before an attacked Dekoichi’s Flip Effect draw. Paired Jinzo fixtures check a set Mirror Force is unavailable while Jinzo is face-up, then becomes a legal and resolving attack response after Book of Moon turns Jinzo face-down. Paired Magician of Faith fixtures check Spell recovery after a Flip Summon, the opponent card reveal, and continued Flip Effect resolution when Book of Moon turns Magician of Faith face-down. Enemy Controller fixtures check both effect choices, Tribute as an activation cost for temporary control, and End Phase control return. Cyber Jar and Ground Collapse fixtures cover public five-card reveal order and a two-zone lock respectively. The remaining timing and card-specific cases below are untested.

**Work:** Create source-backed regression fixtures for first-turn draw, summon response and Ignition priority, chain construction and resolution, trigger ordering and missed timing, Damage Step restrictions, flip effects, summon negation, historical field spells, the April 2005 list, and representative pre-errata card rulings. Track unresolved rulings in `docs/goat_rules.md` with the chosen interpretation and evidence.

**Exit:** Every required fixture passes with pinned engine assets, or is marked as a known incompatibility that blocks a GOAT-correct claim. Run differential checks against documented examples or independently observed duels where practical. Expand the legal-card test corpus beyond the initial fixture decks.

## M3 — Evaluation and data

**Status: in progress.** Seeded tournament runners swap seats for each deck matchup, record individual outcomes, report seat and matchup splits, and give paired score and Wilson intervals. A spawned-process runner reproduces the sequential results on a native fixture and has a measured two-worker throughput example. A restricted-fixture baseline report is in [the evaluation log](evaluation.md). Schema v12 decision trajectories record face-up monster ATK, DEF, and counters alongside bounded public events, field-slot known-card memory, a public Scapegoat restriction, public Deck-top reveals, active disabled zones, recipient-scoped private reveals, and the player's initial Main Deck composition; they can be replayed against the native engine with exact observation, legal-action, result, deck-content, rules-profile, and loaded-asset comparisons. An offline browser viewer renders these player-visible decisions without card art or intermediate animations. Earlier fingerprinted recordings remain verifiable. Broader deck families, held-out opponents, authorized human replay reconstruction, training/evaluation separation, and parallel-worker memory measurement remain outstanding.

**Work:** Build seeded agent tournaments with deck and matchup splits, seat swaps, confidence intervals, and held-out evaluation opponents. Measure duel throughput, decisions per second, runtime memory, and initialization overhead on named hardware. Validate self-play trajectory round trips. Investigate `.yrp` and `.yrpX` reconstruction; ingest human games only when permission, legal-action recovery, and player-visible knowledge can be established.

**Exit:** A reproducible benchmark report and tournament report exist for the tested core/assets/decks. Replay support is claimed only for formats that have parser and reconstruction tests.

## M4 — Learn a competitive policy

**Status: in progress.** A PyTorch policy scores variable-length legal action sets from visible observations, and behavioral cloning fits replay-verified fingerprinted trajectories into versioned checkpoints. Feature version 2 distinguishes multi-target choices by visible target location even when IDs are hidden; version 3 uses field-slot memory of publicly known facedown opponent cards; version 4 encodes disabled zones and multi-zone choices; version 5 separately pools the player's initial Main Deck composition; version 6 distinguishes Attribute, number, and card-name announcements; version 7 distinguishes ordered card choices; version 8 encodes visible current monster stats and counter counts. Old checkpoints retain their versioned encoders. Demonstrator-seat metadata filters heuristic or self-recorded CLI-human decisions after full-duel verification. The checkpoint evaluator runs paired, seat-swapped tournaments on seeds excluded from training and supports direct checkpoint opponents. A heuristic-imitation baseline won 15/16 versus RandomAgent and 9/16 versus HeuristicAgent on held-out vanilla-fixture seeds; a version-2 retrain matched these results. Direct version-2 versus version-1 evaluation on experimental control/Chaos decks was 17/32, an inconclusive result with unaudited rules and visibility. Initial terminal-reward self-play from random imitation and two runs from the heuristic baseline did not demonstrate a greedy-policy strength gain. Version 5 was trained on one random-play Ground Collapse fixture and evaluated on held-out seeds: 11/16 versus RandomAgent and 7/16 head to head versus version 4; version 4 scored 14/16 versus RandomAgent on the same schedule. This does not show a gain from the Deck feature. Version 6 has no competitive result yet. No authorized tournament-human training set, robust held-out competitive result on audited deck families, or strength claim exists yet.

**Work:** Implement a PyTorch policy that scores variable-length legal actions from visible observations. Establish random and heuristic baselines first. Train behavioral cloning on verified demonstrations, then self-play with a historical checkpoint pool and held-out deck families. Compare PPO or other algorithms on win rate and stability rather than selecting one in advance.

**Exit:** A versioned model beats the baseline agents over held-out seeds and decks with confidence intervals, and its decisions use no hidden engine state. Record training compute, data provenance, and evaluation protocol.

## M5 — Search and other formats

Evaluate policy-guided search and belief sampling only after M2 and M4. Search must sample hidden information from a player-consistent belief and must never inspect the real hidden state when choosing actions. Add Edison as a separately validated rules profile, not a changed banlist.

### Possible Stardust PC-port integration

Keep training in Python. Define a versioned, game-independent decision boundary: the game supplies a player-visible observation and legal actions; the agent returns an action identifier. When Stardust exposes those decisions in a PC port, implement a small C or C++ bridge and native model inference. Stardust's 2009 rules, card IDs, and action protocol need their own adapter and validation; GOAT checkpoints should not be assumed directly compatible. This is future work and does not block the GOAT milestones.

## Immediate next work item

Prioritize M1 and M2 fixtures for cards central to 2005 Goat Control and Chaos decks, continuing with the remaining high-play control and Chaos staples after the Metamorphosis, Thousand-Eyes Restrict, and Tsukuyomi fixture. Audit their legal choices, prompt semantics, and hidden-information boundaries, including Extra Deck interactions. Continue M2 with source-backed timing and ruling fixtures before training. Keep each implementation change small enough to demonstrate with a command, test, and documented limitation.
